# Cantrip

macOS command bar. Rust app drawn with [Rune](https://github.com/anomalyco/rune) (`app/`) + bun spell host (`runtime/`) talking JSON lines over stdio.

## Rules

- The protocol lives in two places: `runtime/src/host/Protocol.ts` and `app/src/protocol.rs`. Change both together.
- The host's stdout is the protocol. Never write to it except through `Wire.send`; `console.*` is redirected to stderr (the host log).
- Every view in a session is a frame with its own Scope, query, and action handlers. A `Ui` is bound to one frame (depth). Keep it that way — `render` must never target "whatever is on top".
- Daemons (`runtime/src/host/Daemons.ts`) are host-owned, not session-owned: one Scope each, forked from the host's. Every way the host ends (stdin EOF, SIGTERM) must close that scope so finalizers run. Insomnia's finalizer is what turns sleep back on. Never `process.exit` before the layer scope has closed.
- A daemon's finalizers learn why it stops via `Daemon.stopReason`. Only Restart Host (the app sends `handoff` before SIGTERM), `cantrip handoff` (run by `scripts/bundle.sh --install`), and reloads count as hand-overs; stdin EOF or a bare SIGTERM is always `"shutdown"`, so a quit or crash still fails safe.
- Reload only re-imports entries whose files changed, and keeps the previous module if the new one fails to load. A daemon whose exported object is unchanged keeps running. Don't make a reload restart daemons wholesale.
- CLI commands (`runtime/src/host/Commands.ts`, `runtime/src/cli/client.ts`) run in the host, never in a separate process, so a daemon's command shares its live state. The socket frame format is documented at the top of Commands.ts; change the client with it. Link management must only ever touch symlinks that point at Cantrip's shim.
- Grimoire entries are disabled by default: only those listed in the grimoire's `spells.json` (`enabled`) are imported; the rest stay on disk unloaded. A new grimoire gets `{ "enabled": [] }`; one without the file (from before) is migrated by enabling everything in it. The host sends every entry with the spell list (`commands.entries`, `WireEntry`), and the Grimoire book (`views/book.rs` `rows`) lists disabled ones faintly; ↵ on one sends `setEnabled`. ⌘K → Disable Spell turns one off. The CLI has `cantrip spells` / `cantrip enable|disable <name>`.
- Spells import `cantrip` and `effect/*`; the host symlinks both into the grimoire's `node_modules`. Don't make spells install packages.
- `Bun.resolveSync` before dynamic `import()` in the Registry works around a Bun 1.3.14 resolver bug with newly created files. Keep it.

- The app (`app/`) is a Rune app. Rune draws the panel and the HUD; `app/src/platform/` is the AppKit Rune doesn't do (status items and their menus, SF Symbols rasterized to pixels, NSWorkspace, user defaults, the login item). State lives in `store.rs`; it reaches the outside only through `services.rs`, which headless runs and tests leave empty so effects land in `Services::log`.
- Check UI work headlessly: add or adjust a scene in `app/src/fixtures.rs`, render it with `target/release/Cantrip --scene NAME --snap out.png` (or `--tree`, `--script`), and cover behaviour in `app/src/tests.rs`. Headless runs never start the host, the menu bar or NSWorkspace; `app/scripts/search.json` is a sample `--script`. The opening and closing animations are `El::sequence` choreography in `app/src/views/intro.rs` and `outro.rs` (the `closing` scene shows the exit; render it with `--at`), replayed per opening; see the opening frame by frame with `--scene opening --script scripts/open.json --strip strip.png --start 0.08 --frames 30 --every 3 --cols 5`.
- The wand in the search bar is a 3D model rendered on the CPU (`app/src/views/wand.rs`, rasterizer in `wand/raster.rs`) into a `Pixels` image from `AppSpec::poll`, on the frame clock. Each opening (about 0.6 s) it comes in first as a glow, large and pointing at you in the middle of the bar to come, casts the bar (the shell scales out of `wand::hero_tip()` from `intro::GROW`; everything inside waits for it), then turns to point along the vector home and flies there tip first, shrinking, springing into its resting pose as it lands by 0.5 s, drawn over the window by `hero_view` into a second, fixed-size `Pixels` until it lands. Its behaviour is a state machine (`wand/motion.rs`): moods held while something is true (typing, no results, hovered) and one-shot gestures the store cues (`wand.cue`) for events (selection moves, casts, closing). Typing goes through `wand.edited`: `wand/spells.rs` hides each new character until a spark from the tip lands on it, drawn as field spans and one `Shape` layer that the view rebuilds every frame while spells fly. A frame depends only on the frame clock and the cues given, so headless renders repeat; every shown frame asks for the next with `tx.wake_after` (at once while anything moves, 30 fps idle; `Pixels::set` in poll wakes nothing), and nothing draws while hidden, so a hidden bar costs nothing, and Reduce Motion gets a still wand and no spells. Keep it that way.
- Magical themes live in `app/src/views/theme.rs`: Sigil (default) and Arcane. A theme picks the palette and type (`palette.rs`: glows by role, `glow`/`glow2`/`cool`, scaled by `radiance`), the wand's materials and marks (`wand.rs` `marks`, `wand/model.rs` `Looks`), the spells (`wand/spells.rs`, Sigil's in `wand/spells/sigil.rs`), and the opening and closing flourishes; the wand's motion is shared. Each edit's spell keeps the theme it began in. Add a theme by adding a variant and answering each `match` on `Theme`; don't branch on a theme outside those. The choice is `Cantrip::theme`: config.json's `theme` until one is picked in the bar, saved in user defaults. Change Theme (`Builtin::ChooseTheme`) opens `ThemePicker` over the root search; the highlighted theme is worn live as a preview, ↵ keeps it (`Builtin::UseTheme`), Esc or closing the bar puts back the old one. Headless scenes are Sigil; `root-arcane` and `opening-arcane` show Arcane, `themes` the picker.
- Open Grimoire (`Builtin::OpenGrimoire`) shows the grimoire as an ancient book over the root search (`app/src/views/book.rs`, state `Cantrip::book`), its index beside it on the desk (every spell, alphabetical, with its folio; the field searches it, and moving through it turns the pages). Each spell has a spread: its entry under an illuminated initial on the left, with a ledger at its foot (status: enabled, disabled, a daemon running in the menu bar or not, failing to load; how often it's been cast; its file), its incantation on the right (its export's code, read from its file by `Book::source` and cached until spells reload; headless runs only have what fixtures give `set_source`). A leaf between two spreads carries the earlier one's incantation on its face and the later one's entry on its back. ↵ casts, ⌘↵ shows the spell's file (`Config::spell_file`), Back from a spell returns to the book, Esc closes it. Show Grimoire in Finder (`Builtin::RevealGrimoire`) opens the folder. The cover swinging open and the leaves turning are drawn on the frame clock (`Leaves::frame`, from `AppSpec::poll`), like the wand: headless renders repeat and Reduce Motion turns none. There is one book in every theme: its binding (leather, brass, page edges) and its pages are painted procedurally on the CPU into `Pixels` (`views/book/paper.rs`, once per display scale, in parallel, and ahead of time at launch); a theme only changes its inks (`ink`). Pages are pictures of their own over the binding, each right page worn its own way (`Wear`, chosen by folio), so a turning leaf is exactly the page it lifts off and the page it lands on. The pages curve on the GPU: the app's compositor (`views/book/warp.rs`, `App::compositor`) finds the book's effect slot and redraws its backdrop copy through `warp.wgsl`, so the writing bends with the paper; frames without the slot draw as Rune would. Sheets in the air are the compositor's too: each face in the air (up on the right, back up on the left) is drawn flat under a capture slot of its own and drawn back foreshortened, and each is shown landed for one frame before it goes, so nothing jumps. Check animation with frame dumps (`--frames N --out DIR`) and frame-to-frame differences, not stills; `the_shaders_compile` validates the WGSL, which otherwise panics the app when the book opens. Hit-testing still uses the flat layout (it's off by a few points at most). Scenes: `grimoire`, `grimoire-arcane`, and `grimoire-opening` / `grimoire-turning` to render over time with `--at`.
- `scripts/bundle.sh --install` builds a self-contained Cantrip.app (bun inside, in `Contents/Resources/bun/`) and installs it to `/Applications`. The icon is code: `app/examples/icon.rs`; `scripts/icon.sh` re-renders `app/Cantrip.icns` (committed).
- Rune is pinned to a `dev` rev in `app/Cargo.toml` (both `rune` and `rune-kit`), with its toolchain in `app/rust-toolchain.toml` and `rust` in `mise.toml`. Bump them together. Rune colours are linear; use `views::palette::srgb` for sRGB values.

- bun is pinned to 1.4.4 in `mise.toml`, `engines.bun` in `runtime/package.json`, and `MinimumBun` in `runtime/src/host/main.ts`. Bump all three together. Use `mise exec -- bun …` if your PATH has an older bun.

- The repo lives on projects.just-be.dev (`origin`), mirrored to github.com/just-be-dev/cantrip. Every push to `main` deploys prod; other branches deploy previews.
- The root `package.json` + `alchemy.run.ts` deploy the website, cantrip.just-be.dev, where Cantrip is distributed from: the Astro site in `site/` (`Cloudflare.Website.Astro`, a bun workspace; `bunfig.toml` hoists so the Astro build finds `astro`) and an R2 bucket of release zips. `project.ts` reads what the platform's runner provides (`PROJECT_NAME`, `STAGE`, `PROJECT_HOST`, ...). Keep returning `{ url }` from the stack. `rootDir` must stay absolute (`alchemy dev` resolves a relative one twice).
- Releases publish on push: `.github/workflows/release.yml` runs on the GitHub mirror (macOS, since the platform's runner is Linux) for pushes to `main` touching the app, builds with `bundle.sh`, and `scripts/release.sh` uploads through `PUT /api/releases/<version>` with the run's GitHub OIDC token. The site verifies it (`site/src/lib/github-oidc.ts`): issuer, audience = the site's origin, `RELEASE_GITHUB_REPOSITORY`, and that exact workflow on `refs/heads/main`. Keep it secretless; don't add a shared token to prod. Only `alchemy dev` binds a `RELEASE_TOKEN`. Re-publishing a version is a 409 no-op. The site's `/install.sh` is rendered per request from `latest.json`, and does what `bundle.sh --install` does (hand-off, replace, open). The bucket layout is documented in `site/src/lib/releases.ts`. Don't edit `vendor/secrets-alchemy`; it's a vendored copy from the secrets manager.
- The site's screenshots and demo video come from the app's headless scenes: `scripts/site-media.sh` (`mise run site-media`). Re-run it when the bar's look changes. The site wears the Arcane palette (`site/src/styles/global.css`, from `palette.rs`).

## Effect

Effect 4 (stable, `effect@^4.1`). Bare-module imports: `import * as Effect from "effect/Effect"`.
Unstable modules live at `effect/http/*`, `effect/process/*`. Services use `Context.Service` + `Layer.effect` + `.of`;
access a service in a pipe with `Service.use(...)`. Check `runtime/node_modules/effect/ai-docs` and the `.d.ts` files before guessing an API.

## Checks

```sh
mise run typecheck                 # runtime + example spells (tsgo, Effect language service)
mise run check                     # app: clippy -D warnings + tests (Rune Runtime drives keys/clicks headlessly)
mise run snap                      # app: render every headless scene to app/target/snaps/*.png
mise run host                      # drive the host by hand with JSON on stdin
CANTRIP_KEEP_OPEN=1 mise run dev    # run the app without hide-on-blur
```
